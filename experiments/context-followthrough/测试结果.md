# 从真实失误建立的上下文承接测试

已经做出两样可检查的产物：一份精简技能草稿，一套可重放的对话测试。

## 精简规则草稿

`candidate/context-followthrough/SKILL.md` 针对本次问题，区分用户当前处理的对象、要求的操作和讨论任务。前文在评测规则时，技术方案是被比较的材料；“总结一下”应承接比较任务。用户明确改题后，则服从新任务。

这份草稿不要求每轮输出理解过程，也不强制确认。它已经通过 skill-creator 的格式校验，但尚未做独立行为验证，没有安装进个人技能目录，也没有替换已有规则。

原 Proactive Advisor v1.1 已有类似约束。因此草稿的作用是把这一问题压缩为专门的候选规则；不能把改写说成新发现的解决办法，更不能声称比原版更有效。

## 本轮实际运行

冻结三种现有条件：不加载目标规则、加载 intent-check、加载 Proactive Advisor v1.1。每组执行三题，各一次，共九次新会话。候选草稿未参与本轮九次对照。

| 场景 | 基线 | intent-check | Proactive Advisor v1.1 |
|---|---|---|---|
| 两组回答后说“总结一下” | 通过 | 通过 | 通过 |
| 明确改为三句话总结技术方案 | 通过 | 通过 | 通过 |
| 讨论对照结果后问“接下来怎么弄” | 通过 | 通过 | 通过 |

九次运行全部正常结束；六次规则组的成功工具输出均包含完整规则。检查完整可见回答后，三种条件都正确承接对象或服从改题。基线既比较了 A/B 的实质差异，也没有把一次差异说成稳定收益。

评分由本次维护者按预先固定的案例标准检查，非独立盲评。三题均来自同一组材料，每种条件每题仅一次，不能当成九个独立真实用户案例。

## 结论和限制

本轮没有在 Codex 中复现用户回忆的 Work 失误，也没有发现现有两套规则的额外收益。这并不否认原失误，而是说明当前重构输入、会话状态或执行环境没有触发它。

两份 A/B 回答来自原始导出，但开场显式说明了比较意图；失败轮完整前文与用户逐字末句未取回，不能把本轮叫作原样复现。相比长对话中隐含的意图，显式开场仍可能使任务更容易。末轮虽仅写“总结一下”，这项限制仍然存在。

本轮使用本机配置的 Codex CLI，没有在 Work 中运行；没有测试自动调用、真实用户满意或实际返工。规则读取证据不等于行为提升，格式校验不等于草稿有效。

下一次有区分力的测试应保留原使用环境与实际失误发生前的对话，或使用事先冻结的不同领域长对话作为新测试。不要通过反复改写这三题挑选有利结果，也不要因这轮全通过就继续扩充规则。

## 可用成果

这套测试能在以后修改规则或更换模型时回归检查：助手是否重新答原题，是否忘记当前工作，是否在用户改题后还坚持旧目标。它能记录具体退步；目前还不是一个会自动判断意图的程序，也不能强制 Work 每轮遵守规则。

查看 `recorded/results.json` 和 `recorded/loading-audit.json` 可逐条核对回答与加载工具事件；`recorded/ratings.json` 保存行为检查依据。公开副本删去了创建者本机目录身份，没有发布原始内部运行日志。运行方法见 [README.md](README.md)。
