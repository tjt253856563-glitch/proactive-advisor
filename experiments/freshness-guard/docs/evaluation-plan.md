# 普通Chat对照计划（尚未执行）

目标不是证明插件能安装，而是比较自然提问下是否减少无证据的过时事实，同时控制额外耗时、拒答和用户负担。

## 三种条件

1. 同一普通Chat模型、无Freshness Guard插件。
2. 同模型、已安装插件，但自然提问不点名。
3. 同模型、显式选择Freshness Guard。

每题单独新会话，隔离历史与项目指令。记录客户端、套餐、模型、检索工具、时间、插件版本、是否能观察到真实加载轨迹。无法做到隔离就披露污染，不宣称随机对照。

## 案例与金标准

预先冻结12个以上当前事实问题，覆盖高管任命宣布与生效、模型预告与发布、付费计划与账户权限、截图/旧摘要、同范围冲突和稳定知识。运行前由独立核验者保存适用官方原文及日期；答案需按采集时点判定，不能把固定人名当永久真值。

三条件配对且随机顺序；同题尽量短时间窗口完成。对运行期间事实改变的题标记无效而非算错。不把同源转载当独立来源。

## 分开统计

- 事实正确率与无依据确定性断言率。
- 自动选择率、实际读取率及检索/原文覆盖率；工具轨迹不可见时记不可观察。
- 证据是否支持具体实体、时间、套餐和地区。
- unknown/拒答比例，误拒答也会损害实用性。
- 稳定知识是否多余搜索。
- 完成时间和用户额外操作次数。
- 结构检查通过率单列，不与事实正确率混合。

评分者尽量不知道条件。按原始输出评分，保留失败、工具错误和受阻；未评分不变成PASS。报告样本量和不确定性，不用小样本百分比宣传“解决幻觉”。
