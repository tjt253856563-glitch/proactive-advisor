# Freshness Guard v2.0 测试报告

核验日期：2026-10-19，Asia/Singapore。联网证据主要来自 12:25 与 14:05 后两轮工具执行；JSON 中记录的是台账完成时间，不是 HTTP 请求逐条精确开始时间。测试环境为本次云端 Work，有网页检索、正文打开、文件与 Python 工具。未购买服务、未验证其他公司的用户账户。

## 结论与指标

v2 已从纯文字守则升级为“断言限定 → 官方正文核验 → 时间/冲突处理 → 证据台账 → 结构检查”的可运行流程。当前环境可以执行；这仍是 AI 工作流，不能保证永不使用旧信息，也不是常驻情报数据库。

| 测试层 | 分母与结果 | 能证明什么 |
|---|---|---|
| Skill 基础格式 | 官方 quick_validate.py 通过 | YAML、命名等基础格式合格 |
| 离线结构回归 | 40/40，100% | 给定输入按证据门槛被接受或拒绝；不是事实准确率 |
| 主执行者联网案例 | 16 条均执行；14 条有限范围 verified，2 条 unknown | 断言级官方证据可核验率 87.5%；unknown 不算核验成功 |
| 独立显式调用 | 4 个问题；7 条断言中 6 verified、1 unknown | 另一个新代理能读 Skill、搜索、开原文、运行检查；不与主样本相加 |
| 未点名 Skill 的调用 | 1 次包含 3 问的任务，实际选择并读取 freshness-guard；2 人事问题检索、稳定物理问题无额外搜索 | 本环境单次选择及执行成功；样本太小，不是全局触发可靠性统计 |
| 保存与发现 | git 提交推送；平台 Skill 列表可见；skills.read 成功 | 本环境保存、发现、读取成立；普通手机新聊天的长期自动触发未验证 |

尚未做 v1/v2 随机对照测试，不能量化“错误减少多少”。独立代理与主代理使用同一类底层模型和检索设施，也不等于独立事实金标准。计分基于执行记录和人工范围审查，脚本只自动检查结构。

## v1 审查与修改

原包仅 SKILL.md 和 7 个文字用例，无执行脚本、结构化台账或跑分记录。其官方优先、区分计划/账户、不能因没搜到就说没发布的方向正确。

| 漏洞 | v2 修正 |
|---|---|
| 用户没写“最新”也可能在问现任/当前权限 | 在 description 加入隐含当前状态的触发，不只依赖关键词 |
| 较新截图优先容易被伪造/裁切误导 | 截图只作线索；正文、身份和上下文独立核实 |
| “已搜索”可能其实只看到摘要 | verified 必须有打开原文与章节定位；记录检索服务抽取的缓存限制 |
| 日历日期、事件日、修订日混用 | 未知为 null；不把抓取日、footer、URL年月当发布日 |
| 没有源间冲突的裁决方法 | 先对齐范围，再检查明确替代链；未解冲突只能 unknown |
| 搜索无关结果时继续猜 | 改查询/日期过滤或切引擎，去官方频道；仍不足时明确停止 |
| 自动生效仅靠口头保证 | 分开保存、目录读取、平台发现、显式执行、自动选择五层验证 |
| 没有可执行验收 | 添加 Python 标准库检查器、40 项回归及16项动态用例 |

核心流程只有 5 步；路由与证据字段放参考文件，没有增加统一 24 小时“有效期”或无限搜索循环。

## 实际失败、修正和能力边界

1. **检索失败**：主执行者一轮 system1 带 recency 的四查询返回大量不相关结果；换成实体词+域名限定的 system2 后命中。独立代理也遇到官方频道 Internal Error 及无关结果。已执行替代路径，未从失败推出“没有发布”。
2. **索引/版本不一致**：Skills 搜索摘要曾显示 Updated 12 days ago，打开正文为 Updated 2 months ago。只能证明工具返回内容不一致，不能证明真实索引延迟了多少天。官方页面抽取不等于无缓存直连。
3. **漏掉新模型的路径偏差**：只搜 Llama 或看 Meta AI Blog 首屏会停留在旧型号；独立代理从 Meta Newsroom 找到 Wonder/Full。主执行者已重新打开复核并纳入台账。已把“旧模型名限制查询”作为实测失败路径记录，未把旧结果冒充最新。
4. **检查器实际缺陷**：首次检查16条记录时，about.google 未包含在 Google 官方域名集合，导致 G-L 被错误拒绝。原失败日志保存在 live-contract-results-before-fix.json；修正并加入专项回归，最终16条全部结构检查通过。
5. **测试时缺文件**：显式调用代理最初读取检查脚本时文件尚未生成；随后补齐，代理实际运行并通过。保留前后过程，不声称第一次就完整运行。
6. **额度受阻**：首次独立代理请求因 usage limit 失败。用户要求继续后重试成功；不把首次失败删除，也不计为模型答题错误。
7. **语义盲区**：自动探针把明显伪造的断言配上人为声明 supports_exact=true，检查器仍接受。这是已证实的能力限制；它不能替代真实检索、原文语义审查或来源独立性判断。
8. **日期缺失**：OpenAI 可见正文无发表日、Meta 双日期无标签。没有推测填空；verified 仅指发布存在。
9. **未验证**：分钟级实时帖检索、全网“没有更新”证明、无缓存官网直连、真实第三方账户权限、所有 Plus 账户的安装权、普通新聊天长期自动触发、持续后台监控、与 v1 的准确率提升。
10. **模拟覆盖不等于行为证明**：断网、同源转载、假域名、未解冲突等在40项离线数据中检查了声明门槛；没有真实断网故障注入、伪造截图鉴定或所有冲突场景的独立模型评测。

## Plus 安装研究

[官方 Skills 帮助页](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)本轮列出 Business、Enterprise、Healthcare、Edu，没有列 Plus；并说明不同产品与界面可有差异。因此不能据该文承诺“Plus 普遍支持”，也不能仅凭遗漏就断言本账户绝对不支持。

本环境实际证据更具体：个人 Skills 工作区可写入并推送，freshness-guard 已出现在平台技能列表，支持通过 skills.read 读取；未点名的独立任务也选择并读取执行了它。可以确认本次 Work 环境支持保存、发现和执行。没有操作用户手机 Skills UI，ZIP上传扫描与手机端安装入口未验证。官方适用范围与本环境能力差异保留，不擅自解释为某个灰度或特定套餐政策。

可重复替代方案：完整 Skill 与路由放入 Work 项目资料，添加明确项目指令，任务首句要求读取并核验；或每次上传附带的 Work-reuse.md。它依赖上下文与工具，不冒充原生安装。具体步骤见单独使用说明。

## 复现

Python 3.10+，仅标准库。在完整交付包解压目录执行：

```bash
python freshness-guard/scripts/run_tests.py --output rerun-offline.json
python freshness-guard/scripts/check_evidence.py evidence/live-evidence.json
python freshness-guard/scripts/check_evidence.py evidence/forward-live.json
```

前者自动重跑40项结构回归；后两者检查已有证据快照，不会重新联网。重新核验事实时，在 Work 明确调用 Skill，读取16项 live-cases，逐条实际检索/打开并生成新的时间戳台账，再执行检查器。不要把今天的14条结果当作未来固定真值。

原始v1包、测试代码、初次失败日志、最终日志及独立代理记录均随ZIP提供。程序的退出码0只代表所执行检查通过。
