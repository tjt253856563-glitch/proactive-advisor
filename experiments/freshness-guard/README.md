# Freshness Guard：时效核验与 Chat 可靠性实验

状态更新：2026-10-22。此目录公开目前遇到的问题、实际源码、证据记录和未完成的验证。

起因是一次“现任公司 CEO”问题被凭旧信息回答。用户关心的不是某个姓名，而是：连普通事实都可能自信答错时，如何信任其他不熟悉的回答？正常使用不应要求用户先知道答案，再监督模型。

本项目尚未证明能够稳定改善普通 Chat 的事实可靠性。规则可读取、脚本可运行、插件可创建，都不等于模型回答更准确。

## 已有成果

| 成果 | 当前证据 | 不能推导的结论 |
|---|---|---|
| v2.0 工作流 | 官方原文优先、事件/发表/生效时间分离、索引版本差异与冲突处理、证据台账 | 不保证全网实时覆盖 |
| v2.0 结构检查器 | 历史40/40项通过，本次重跑40/40 | 不是40轮独立模型测试，更不是100%事实准确率 |
| 联网核验记录 | 2026-10-19，16条执行记录，14条有限范围verified，2条unknown | 87.5%是已归类断言的可核验比例，不是模型效果提升率 |
| 显式调用试验 | 另一个代理处理4问，7条断言中6 verified、1 unknown | 不与主样本合并成独立准确率；使用相近模型和检索设施 |
| 未点名调用观察 | 1次混合任务，代理实际读取规则；2个人事问题检索，稳定物理问题未额外搜索 | 样本太少，不能证明普通手机Chat长期自动触发 |
| v2.0.1 Chat插件适配 | 包含Apple；修正产品元数据；无代码工具时明确未运行脚本；43/43结构回归 | 包含Apple测试只验证结构门槛，未重跑Apple真实人事核验 |
| 私人插件保存 | 当前用户账户创建成功，读取回存的规则与策略文件 | 不是已验证普通Chat安装/调用；私人链接不作为公共安装入口 |

脚本检查 `supports_exact` 等核验者填写的字段。一个内容明显错误、但被人为标记为原文支持的断言仍能通过。这一边界已实际测试并保留在结果中。

## 本地复现

从仓库根目录运行，Python 3.10+，仅需标准库：

```sh
python experiments/freshness-guard/plugin/skills/freshness-guard/scripts/run_tests.py
python experiments/freshness-guard/plugin/skills/freshness-guard/scripts/check_evidence.py experiments/freshness-guard/recorded/2026-10-19/live-evidence.json
python experiments/freshness-guard/package.py --output freshness-guard-plugin.zip
```

第一条是43项确定性结构测试；第二条检查历史台账，不联网；第三条从已公开源码生成可上传私人插件的包，不负责安装或验证Chat。

## 为什么还没有证明解决问题

Skill依赖模型选择并读取它，依赖现有搜索工具，还依赖模型理解原文。安装不会替代这些环节，也不能修复Chat平台本身的默认行为。我们没有普通Chat下“无插件/有插件”的随机配对独立评分结果，没有长期触发率，没有真实账户权限全面验证。

因此目前定位是“可审查的辅助核验工作流”，不是“可靠性问题已解决”。下一步应补真实Chat对照，而不是继续增加规则数量。

## 记录来源与隐私

此目录由2026-10-19/20会话产生的本地/已保存交付物恢复整理；没有重建不存在的原始CEO错误回答。事故属于用户报告，缺少完整原始失败轮，不能冒称已复现。代理过程文本是过程记录和自述，不是独立、不可伪造的工具审计日志。

公开副本替换了内部工作区路径，省略私人插件ID、账户安装链接、邮箱和截图；保留官方公共资料URL、规则、代码与测试结果。原始交付包中的二进制嵌套包未重复上传。源码沿用仓库MIT许可证。
