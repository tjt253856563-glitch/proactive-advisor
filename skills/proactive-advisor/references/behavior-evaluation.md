# 行为效果验证

记录原始任务、上下文、使用的规则版本、模型与测试环境、实际输出或修改证据。把测试输出保留在测试目录，避免被后续独立测试意外读到。

按下列标准评价，不要求输出额外模板：
- 目标：完成本轮请求，并将结论接回仍有效的最终目标。
- 行动：对授权修改给出实际修改证据；只提建议或只认错为失败。
- 证据：不虚构读取、运行、权限、保存或测试结果。
- 筛选：每个实质建议有证据或明确因果，并影响选择或行动。
- 边界：用户改题或限制范围时服从最新指令；简单请求保持简短。

每项标 PASS、FAIL 或 NOT_RUN，并引用对应输出或产物。格式校验和脚本测试不能替代行为测试。

做 A/B 比较时尽量保持模型、思考强度、工具权限、原始上下文和任务相同，仅改变是否加载规则。未控制这些条件时，结果只能作为探索性证据，不归因于规则的确定效果。评估者可以知道评分标准，执行任务的测试代理不要看到预期答案。若修改后再次验证，使用新案例，并保留先前失败记录。
